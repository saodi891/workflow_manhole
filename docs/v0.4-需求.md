# v0.4 需求：窗口内部状态还原

## 目标

工作流现在只能还原窗口的**位置和尺寸**。v0.4 希望在还原窗口之后，进一步恢复某些特殊程序**窗口内部**保存时的状态：

1. **浏览器（Edge / Chrome）**：还原保存工作流那一刻打开着的标签页。
2. **文件资源管理器**：还原保存那一刻窗口打开的文件夹路径。

## 背景 / 难点

现有工作流机制 = 「启动 exe + 用 Windows API 移动窗口」，对窗口**内部**一无所知。
标签页 / 当前路径这类信息在程序自己进程内部，没有通用 Windows API 能直接读到，
只能针对每个软件单独想办法，各有硬伤。

## 已调研的实现路径与取舍

### 文件资源管理器（相对可行，倾向做）
- **抓取**：通过 COM 接口 `Shell.Application`（`ShellWindows`）枚举当前打开的
  资源管理器窗口，读每个窗口的 `LocationURL` / `Document.Folder.Self.Path` 拿到路径。
- **还原**：`explorer.exe "D:\目标路径"` 直接开到指定文件夹。
- **评价**：纯 Windows 能力，不依赖任何私有格式，是这几个里最干净的。
  代价：多加一段 COM 交互代码（可用 `ctypes` + `comtypes` 或纯 win32 COM）。

### 浏览器（三条路，都不干净）
- **A. 命令行传 URL**：`chrome.exe https://a https://b` 能开指定标签页。
  但要先知道 URL —— 得去读浏览器的会话文件（`User Data/Default/Sessions/` 下的
  私有二进制 SNSS 格式，Google/Microsoft 未公开，版本一变就可能崩）。**风险高、易失效，不推荐。**
- **B. 靠浏览器自带「恢复上次会话」**：在浏览器设置里开「启动时继续上次打开的页面」。
  井盖只管启动，标签页由浏览器自己恢复。**零代码、最稳，但不受井盖控制** ——
  它恢复的是「上次关闭时」的，不是「保存工作流那一刻」的。
- **C. 手动维护 URL 列表**：让用户在井盖里为某个配置手动填「要打开哪些网址」，
  启动时用命令行传进去。**可控、稳定**，但要手动录入，不是自动抓当前标签页。

**倾向**：浏览器走 C（手动 URL 列表）。自动抓当前标签页（A）依赖浏览器私有会话格式，
浏览器一更新就坏，维护成本过高，不做。

## 待定 / 需与用户确认
- 文件管理器路径还原：确认是否要做（倾向做）。
- 浏览器：C（手动填 URL）还是干脆不碰、只在文档里建议用户开浏览器自带的会话恢复（B）。
- COM 依赖：文件管理器抓路径若用 `comtypes` 会引入第三方依赖；能否用纯 ctypes 调 COM
  避免依赖，需评估工作量。（项目一贯偏好零第三方依赖。）
